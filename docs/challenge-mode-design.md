# 挑战版「墨隐」设计方案

> 定位：与现有经典版并列的第二个玩法。经典版 = 找数字（视觉搜索），挑战版 = 记位置（空间记忆）。
> 铁律：**不修改经典版的任何现有行为**。所有改动只有两类 —— 新增文件、给现有组件加默认关闭的可选 prop。

---

## 1. 一句话玩法

数字在方格上**闪现几秒后全部隐去**，纸面只剩空格。玩家凭记忆按 1 → N 顺序点回去。
点对 → 数字浮现 + 响一个音；点错 → 罚时 + 少一格命；命用尽或超时 = 记忆断裂。

---

## 2. 核心循环（一局的四个阶段）

| 阶段 | 时长 | 盘面 | 玩家能做 |
| --- | --- | --- | --- |
| `countdown` | 3s | 空白纸格 | 无 |
| `memorize` 记 | `flashMs` | 数字全部可见，末尾 400ms 整体渐隐 | 无（点击冻结） |
| `recall` 忆 | 不限时 | 纸格留框、数字全隐 | 按顺序点 / 窥看 |
| `settle` | — | 定格 | 无 |

关键细节：

- **格子边框必须留着**。数字隐去后仍是「一张方格纸」，玩家记得住「第 2 行第 3 格」，但记不住「一个纯白矩形里的某个点」。留框是把难度从「不可能」拉回「很难」的唯一手段。
- **当前该点的数字显示在 HUD 大字上**（格子里不显示），否则无从下手。
- **点对后该格数字永久浮现**，玩家能看到自己的进度，也顺便减少了后续记忆负荷。
- **点错不揭示正确位置**，只红闪当前格 + 闷响。揭示等于白送一个答案。

推导口径（写进 `data/challengeLevels.ts` 的生成函数，不手填 14 份）：

- `flashMs = n × perCell`，`perCell` 从 1.26s 递减到 0.59s（每关约 −6%）
- `gold = n × 1.1s + 1s`、`silver = n × 1.9s + 2s`
- `lives = max(2, ceil(n / 4))`

> 第一版 perCell 是 1.4 → 0.7，实测反馈「偏长」—— 玩家扫完还有一小段空等，那段空等不加固记忆、只让人分心。整体压 10% 后是现在的表。

难度轴只有两条：**格子数** 与 **闪现预算**。同布局重复出现（第 3/4 关、第 8/9 关）靠缩短闪现区分，不靠加格子，避免 16 格一次性砸到玩家脸上。

### 3.1 圆形盘面（第 12、13 关）

形状与经典版的圆形卡**完全一致** —— 直接复用 `utils/circleLayout` 的 `buildCircleCells`，
按半径分圈、按角度分格，第 k 圈有 2k-1 格，累加正好 n²，所以圆形盘面的格数永远是平方数。

| 圈数 | 格数 | 在关卡里的位置 |
| --- | --- | --- |
| 3 | 9 | 第 12 关（接在 3×4 之后） |
| 4 | 16 | 第 13 关（终章 4×4 方阵之前） |

因为「不超过 16 格」这条上限，圆形只有 3 环和 4 环两种可选，所以正好各出一关。

**为什么放在终章之前、且数量先退一档**：换形状等于换一套记忆坐标 —— 方阵能复述成「第 2 行第 3 格」，
扇环只能记「外圈偏右下那个」，无法用行列语言编码。所以第 12 关的格数从 12 退回 9（新形状先认形状），
每格预算也放宽到 0.70s；第 13 关满 16 格给 0.66s；终章 4×4 方阵给 0.63s，仍是 16 格里最紧的一关。

**圆形的实现要点**：

- 盘面宽度交父容器，高度用 `padding-bottom: 100%` 撑成正方形（`height: 100%` 在「宽未知、高由宽决定」时会塌成 0）；真正的圆盘是里面那层绝对定位的 `.circleArea`（内缩 5%）。
- **盘面必须比扇环深一档**（`$memory-ink-soft` vs 格子的 `#f7f4ec`）：缝隙露出盘面，数字隐去后玩家才数得清「几圈、每圈几格」。这一条和方阵「格子边框必须留着」是同一条原则 —— 缝隙看不见，圆盘就是一块白饼。
- 描边用 `box-shadow: inset` 而不是 `border`：border 会和 `padding-bottom: 100%` 的方框算法打架，撑出来的正方形差几个 rpx，圆就不圆了。
- 数字落点仍由 `labelPosition`（扇环中半径 + 中角度）决定，与经典版逐位一致。

> 关卡 id 在这一版发生了位移：原来的 `m-12`（4×4 方阵）顺延成 `m-14`。
> 挑战版存档因此升到 `SAVE_VERSION = 2`，把 `m-12` 的星子/最佳用时搬到 `m-14` ——
> 不搬的话，玩家已经拿到的 4×4 三星会挂到新加的「圆 · 三环」头上。

## 4. 判定与评分

| 事件 | 结果 |
| --- | --- |
| 点对 | 该格 `done` + 数字浮现 + `tap` 音（音高按序号） |
| 点错 | 该格红闪 420ms + 罚时 **+1.5s** + 命 −1 + `thud` 音 |
| 命归零 | `failed`，结算显示「记忆断裂」，并**揭晓整盘答案**（复盘用） |
| 全部点完 | `finished` |
| 窥看（每关 1 次） | 数字闪现 700ms + 罚时 **+4s**，用掉即失去 3 星资格 |

**不设限时失败**。记忆类玩法里「想不起来」本身就是失败，再叠一个倒计时只会逼人乱点，把「回忆」变成「赌博」。时间只进星级，不判生死。

星级：

- ★★★ 零失误 + 未窥看 + 用时 ≤ gold
- ★★ 失误 ≤ 1 + 用时 ≤ silver
- ★ 通关即得

## 5. 音效设计（独立一套，与曲库完全无关）

原则：**只有一个声音系统 —— 敲在纸上的木与石**。不引用 `data/songs.ts` 的任何旋律，不做伴奏，不做背景乐。

### 5.1 点对音：音高 = 序号

五声音阶（D 宫：D E F# A B），D4 起，每 5 个音升一个八度，两个八度内循环：

```
i = 数字 - 1
freq = 293.66 × 2^(floor(i/5)%2 + [0,2,4,7,9][i%5]/12)
```

- 2 格：D4 → E4
- 9 格：D4 … B5
- 16 格：走满两轮八度

这条规则让玩家**用耳朵就能确认「我点到第几个了」**，是隐性的记忆辅助，也让每一次点击都有明确的上行趋势 —— 点得越顺，音越高，成就感是听出来的。

### 5.2 其余音效（7 个，实时合成，不占包体）

| key | 时机 | 合成 |
| --- | --- | --- |
| `tick` | 倒计时每秒 | 587Hz 短音，音量压到 0.16，不抢注意力 |
| `reveal` | 数字浮现 | 三音琶音 D5-A5-D6，间隔 60ms，磬音色 |
| `vanish` | 数字隐去 | **古琴散音**：D3（146.83Hz）长余韵 1s + D4 泛音轻点 + 40ms 触弦摩擦 |
| `tap` | 点对 | 见 5.1，木音色，decay 随进度微增 |
| `thud` | 点错 | 110Hz 100ms + 30ms 噪声 |
| `peek` | 窥看 | A5 单音，长尾磬音色 |
| `clear` | 通关 | D5-F#5-A5-D6 四音上行，80ms 间隔 |
| `break` | 失败 | A4→D4 两音下行，180ms 间隔 |

音色配方（`services/challengeAudio.ts` 里两组振荡器参数）：

- **木**：正弦基频 + 0.3×二次谐波，attack 3ms，`exp` 衰减 ≈250ms
- **磬**：正弦基频 + 0.5×三次谐波，衰减 ≈600ms

实现方式：`Taro.createWebAudioContext()` 懒加载 + `osc.start(when)` 绝对时间排程，与经典版 `services/audio.ts` **各持一个 context，互不 import**。经典版的 `initAudio / playNote / playSong` 一行不动。

## 6. 视觉：水墨

不是「换成蓝绿」，而是把整页做成一张画：

| 层 | 做法 |
| --- | --- |
| 纸 | 冷宣纸 `#f3f0e8`（比经典版的暖米黄冷一档，一眼分得清在哪一版） |
| 墨 | 浓墨 `#2b2a26`（主按钮、当前目标数字、盘面数字、进度）/ 淡墨 `#6f6b63`（次级信息、墨晕）/ 焦墨 `#161513`（按下态） |
| 朱砂 | `#a83a2c`，**只做「点」**：印章、命点、点错。全页面积控制在 3% 以内，一多就从水墨变年画 |
| 装饰 | 右上 + 左下两团径向渐变墨晕；大厅底部一道贴边的地平线弧；标题右侧竖排落款「记数字之位置」+ 朱砂方印；关卡页下方一方淡墨大字（壹/贰/叁）填住列表天然的空 |
| 盘面 | 外面裱一层宣纸（淡墨线 + 内衬白边），格子是冷宣纸底、无投影 —— 像「册页里的一方格」，不是「一堆 UI 卡片」 |
| 圆角 | 从 48rpx 收到 8rpx：水墨没有胶囊按钮，只有纸片 |

**「远山」这条试过又撤了**：底部两道超宽椭圆只露上弧，看着像山，实际渲染是两道横贯页面的模糊色带 —— 超宽椭圆的中段曲率根本看不出来，而渐变填充又让它像纸上沾了脏东西，压在「三段」标题后面尤其明显。山形要成立必须有**可见的轮廓**，可轮廓一旦可见就会和内容打架。结论：背景装饰要么是「无轮廓的墨晕」，要么是「有轮廓但压在内容下方很远的字」，中间态的伪山体不成立。

**布局不再是「一列卡片」**：大厅是「标题 + 落款 → 裱好的演示盘 → 上下墨线的战绩栏 → 墨迹式三段进度 → 墨块主按钮」，靠留白与墨线分层，不靠卡片堆叠。

**关卡页反过来：不能垂直居中。** 经典版的关卡页有 36 关、必然撑满，用 `page-center-block` 没副作用；挑战版每段只有 3~5 关，整块居中会把「‹ 墨隐 + 关卡标题」推到屏幕四分之一处，看着像页面塌了。所以这一页改成顶部对齐，底部提示靠 `margin-top: auto` 钉在页脚 —— 列表页就该是「头在上面、脚在下面」。

### 6.1 音效的「古典感」是怎么来的

`vanish`（数字消失）原来是 740→370Hz 的**扫频下滑音**——那是电子合成器的语汇，一响就把水墨意境打散。
改成**古琴散音**：D3 空弦给厚度、D4 泛音给空、一丝极短的触弦摩擦让低频听起来是「弦」而不是「振荡器」。
音高不滑动，让它自然衰减，像笔尖离纸、墨迹收干。

## 8. 入口：已定方案 A（tabBar 第 5 项「挑战」）

小程序 tabBar 支持 2–5 项，现有 4 项。加一项后：演奏 / 关卡 / 曲集 / **挑战** / 我的。挑战 tab 落地在大厅页。

## 9. 实施顺序

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P1 | 数据 + 引擎 + 对局页（含闪现/隐去/点错/命） | 能完整打完第 1 关 |

## 10. 已拍板的决策（原待确认项）

1. **入口**：tabBar 第 5 项「挑战」。（原方案 A）
2. **不设限时失败**，只用命 + 星级。
3. **闪现第一版只做「齐现 + 渐隐」**；「按 1→N 顺序逐个点亮」留作后续。
4. **窥看**：每关 **1 次**、罚 4s、失去满星资格。
