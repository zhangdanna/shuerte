# 挑战版「墨隐」设计方案

> 定位：与现有经典版并列的第二个玩法。经典版 = 找数字（视觉搜索），挑战版 = 记位置（空间记忆）。
> 铁律：**不修改经典版的任何现有行为**。所有改动只有两类 —— 新增文件、给现有组件加默认关闭的可选 prop。

---

## 1. 一句话玩法

数字在方格上**闪现几秒后全部隐去**，纸面只剩空格。玩家凭记忆按 1 → N 顺序点回去。
点对 → 数字浮现 + 响一个音；点错 → 罚时 + 少一格命；命用尽或超时 = 记忆断裂。

---

## 2. 核心循环（一局的四个阶段）

| 阶段 | 时长 | 盘面 | 玩家能做 |
| --- | --- | --- | --- |
| `countdown` | 3s | 空白纸格 | 无 |
| `memorize` 记 | `flashMs` | 数字全部可见，末尾 400ms 整体渐隐 | 无（点击冻结） |
| `recall` 忆 | 不限时 | 纸格留框、数字全隐 | 按顺序点 / 窥看 |
| `settle` | — | 定格 | 无 |

关键细节：

- **格子边框必须留着**。数字隐去后仍是「一张方格纸」，玩家记得住「第 2 行第 3 格」，但记不住「一个纯白矩形里的某个点」。留框是把难度从「不可能」拉回「很难」的唯一手段。
- **当前该点的数字显示在 HUD 大字上**（格子里不显示），否则无从下手。
- **点对后该格数字永久浮现**，玩家能看到自己的进度，也顺便减少了后续记忆负荷。
- **点错不揭示正确位置**，只红闪当前格 + 闷响。揭示等于白送一个答案。

---

## 3. 关卡表（12 关 · 三段 · 全方形）

格子数 = 数字个数（不留空格，避免「空格即无数字」泄露信息）。布局只取横版/方版，手机竖屏友好。

| # | 段 | 布局 | 数字 | 闪现 | gold | silver | 命 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 初见 | 2×1 | 2 | 2.8s | 3.2s | 5.8s | 2 |
| 2 | 初见 | 3×1 | 3 | 3.9s | 4.3s | 7.7s | 2 |
| 3 | 初见 | 2×2 | 4 | 5.0s | 5.4s | 9.6s | 2 |
| 4 | 成串 | 2×2 | 4 | 3.8s | 5.4s | 9.6s | 2 |
| 5 | 成串 | 3×2 | 6 | 6.0s | 7.6s | 13.4s | 2 |
| 6 | 成串 | 2×3 | 6 | 5.1s | 7.6s | 13.4s | 2 |
| 7 | 成串 | 4×2 | 8 | 7.6s | 9.8s | 17.2s | 2 |
| 8 | 满盘 | 3×3 | 9 | 8.1s | 10.9s | 19.1s | 3 |
| 9 | 满盘 | 3×3 | 9 | 6.3s | 10.9s | 19.1s | 3 |
| 10 | 满盘 | 4×3 | 12 | 9.6s | 14.2s | 24.8s | 3 |
| 11 | 满盘 | 3×4 | 12 | 7.8s | 14.2s | 24.8s | 3 |
| 12 | 满盘 | 4×4 | 16 | 11.2s | 18.6s | 32.4s | 4 |

推导口径（写进 `data/challengeLevels.ts` 的生成函数，不手填 12 份）：

- `flashMs = n × perCell`，`perCell` 从 1.4s 递减到 0.7s（每关约 −6%）
- `gold = n × 1.1s + 1s`、`silver = n × 1.9s + 2s`
- `lives = max(2, ceil(n / 4))`

难度轴只有两条：**格子数** 与 **闪现预算**。同布局重复出现（第 3/4 关、第 8/9 关）靠缩短闪现区分，不靠加格子，避免 16 格一次性砸到玩家脸上。

## 4. 判定与评分

| 事件 | 结果 |
| --- | --- |
| 点对 | 该格 `done` + 数字浮现 + `tap` 音（音高按序号） |
| 点错 | 该格红闪 420ms + 罚时 **+1.5s** + 命 −1 + `thud` 音 |
| 命归零 | `failed`，结算显示「记忆断裂」，并**揭晓整盘答案**（复盘用） |
| 全部点完 | `finished` |
| 窥看（每关 2 次） | 数字闪现 700ms + 罚时 **+4s**，用掉即失去 3 星资格 |

**不设限时失败**。记忆类玩法里「想不起来」本身就是失败，再叠一个倒计时只会逼人乱点，把「回忆」变成「赌博」。时间只进星级，不判生死。

星级：

- ★★★ 零失误 + 未窥看 + 用时 ≤ gold
- ★★ 失误 ≤ 1 + 用时 ≤ silver
- ★ 通关即得

## 5. 音效设计（独立一套，与曲库完全无关）

原则：**只有一个声音系统 —— 敲在纸上的木与石**。不引用 `data/songs.ts` 的任何旋律，不做伴奏，不做背景乐。

### 5.1 点对音：音高 = 序号

五声音阶（D 宫：D E F# A B），D4 起，每 5 个音升一个八度，两个八度内循环：

```
i = 数字 - 1
freq = 293.66 × 2^(floor(i/5)%2 + [0,2,4,7,9][i%5]/12)
```

- 2 格：D4 → E4
- 9 格：D4 … B5
- 16 格：走满两轮八度

这条规则让玩家**用耳朵就能确认「我点到第几个了」**，是隐性的记忆辅助，也让每一次点击都有明确的上行趋势 —— 点得越顺，音越高，成就感是听出来的。

### 5.2 其余音效（7 个，实时合成，不占包体）

| key | 时机 | 合成 |
| --- | --- | --- |
| `reveal` | 数字浮现 | 三音琶音 D5-A5-D6，间隔 60ms，磬音色 |
| `vanish` | 数字隐去 | 740→370Hz 下滑 140ms + 30ms 噪声，木音色 |
| `tap` | 点对 | 见 5.1，木音色，decay 随进度微增 |
| `thud` | 点错 | 110Hz 100ms + 30ms 噪声 |
| `peek` | 窥看 | A5 单音，长尾磬音色 |
| `clear` | 通关 | D5-F#5-A5-D6 四音上行，80ms 间隔 |
| `break` | 失败 | A4→D4 两音下行，180ms 间隔 |

音色配方（`services/challengeAudio.ts` 里两组振荡器参数）：

- **木**：正弦基频 + 0.3×二次谐波，attack 3ms，`exp` 衰减 ≈250ms
- **磬**：正弦基频 + 0.5×三次谐波，衰减 ≈600ms

实现方式：`Taro.createWebAudioContext()` 懒加载 + `osc.start(when)` 绝对时间排程，与经典版 `services/audio.ts` **各持一个 context，互不 import**。经典版的 `initAudio / playNote / playSong` 一行不动。

## 6. 视觉：同源不同调

- 纸面、墨色、圆角、纸纹**全部沿用**经典版（`styles/theme.scss`），保证是同一本书。
- 主色从**朱砂 #e85d2a** 换成**靛青 #2f4f6f**：按钮、进度条、强调数字、结算印章都用靛青。一眼能分清「我在哪一版」。
- 记忆条：闪现阶段是一条**从右往左收缩的靛青细条**，最后 400ms 转朱砂色预警；回忆阶段变成「已点 / 总数」的填充条。
- 命：HUD 上 3 个小圆点，点错一个熄灭一个（比数字计数更直观）。
- 结算页除星级外，附一张**缩略答案盘**（纯展示，不可点），供复盘 —— 记忆游戏不复盘等于白玩。

### 7.3 存档

```ts
// key: schulte_challenge_v1
{
  stars: Record<string, number>      // levelId -> 最高星
  bestTimes: Record<string, number>
  bestErrors: Record<string, number>
  cleared: string[]                  // 已通关 id 列表
  totalRuns: number
  settings: { sound: boolean; haptics: boolean }
}
```

独立 key 的理由：经典存档一旦因新字段迁移出错，玩家 36 关的星子就没了。物理隔离是最便宜的保险。

## 8. 入口（两种方案，需拍板）

**方案 A（推荐）· tabBar 加第 5 项「挑战」**
小程序 tabBar 支持 2–5 项，现有 4 项。加一项后：演奏 / 关卡 / 曲集 / 挑战 / 我的。挑战 tab 落地在大厅页。
代价：需补一对 81×81 的图标（靛青墨块 + 方框），tabBar 从 4 格变 5 格，间距略窄。

**方案 B · 首页加一张入口卡**
在首页「三卷」上方插一张靛青描边的卡「墨隐 · 记数字的位置」，点击 `navigateTo` 大厅。
代价：入口较深，玩家可能一直没发现挑战版存在；但零改动 tabBar。

## 9. 实施顺序

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P1 | 数据 + 引擎 + 对局页（含闪现/隐去/点错/命） | 能完整打完第 1 关 |
| P2 | 存档 + 结算页 + 关卡地图 + 大厅 | 12 关可顺序推进、星数落档 |
| P3 | 音效 + 记忆条 + 命点 + 答案复盘 | 点对音高随序号上行，无杂音 |
| P4 | 入口（tab 或首页卡）+ 我的页统计 + 分享 | 分享卡片带挑战版成绩 |

每阶段结束跑一次 `npm run build:h5` 自检，并按 AGENTS.md 更新台账。
