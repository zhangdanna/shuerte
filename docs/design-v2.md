## 0. 一页结论

| 维度 | 现状 | v2 要做的事 | 一句话理由 |
| --- | --- | --- | --- |
| **画面** | 6 色循环格子 + 日落橙 + 粉渐变，颜色在抢注意力 | 收敛为「**乐谱纸 + 墨 + 一点橙**」三色体系；格子回到单色纸面 | 舒尔特的核心是"找数字"，任何多余的颜色都是噪声。**简化不是变丑，是把注意力还给玩法** |
| **趣味** | 只有缩放/闪红两种动效 | 五个低成本高感知的趣味点：音符轨迹、目标呼吸、连击光环、结算唱片、关卡唱片角标 | 趣味要挂在"玩法"上，而不是加装饰 |
| **模块** | 首页只有一个按钮；排行榜是空壳页；星星只进不出 | 4 Tab 信息架构；新增「每日一曲 / 曲集 / 成就 / 引导 / 分享」；星星做消耗出口 | 现在缺的不是功能，是**"明天为什么还要来"** |
| **声音** | 4 个提示音（tick/click/error/success） | **格子即琴键**：顺序点对 = 按乐谱演奏一首完整钢琴曲；通关收集曲子，可回放 | 把"训练工具"变成"我弹了一首曲子"，这是本品类最强的情绪钩子 |

**三个关键判断**（后面各章展开）：

1. **音符顺序永远等于点击顺序**。倒序关不是"倒放音乐"，而是把数字与乐谱位置反向映射 —— 玩家依然听到正着走的旋律。这是音乐系统能成立的前提。
2. **不播背景音乐**。只有玩家自己弹出的声音。既省资源、又契合"专注训练"的定位，还让每一次点击都有"是我弹的"的归属感。
3. **音乐不影响星级**。星级仍由用时/失误决定；音乐只给"演奏评级"（S/A/B/C）。否则两种评价体系会互相打架，老玩家的成绩也会失真。

## 1. 现状诊断

### 1.1 视觉

| 问题 | 具体表现 | 影响 |
| --- | --- | --- |
| 颜色过载 | `GridCell` 按 `(value-1) % 6` 循环 6 组「浅底 + 同色数字」 | 8×8 时有 64 个彩色块；颜色成为额外的视觉维度，**干扰目标搜索**，也让画面显得"花"而不是"简洁" |
| 品牌感弱 | `#FF6B35` + 粉色渐变背景 + 胶囊按钮 + emoji ⭐ | 是通用小程序模板的观感，缺少"这款游戏独有的记忆点" |
| 首页空 | 标题 + 9 宫格装饰 + 一个按钮 | 首屏没有回答"我今天该做什么"，回访没有理由 |
| 对局页信息碎 | HUD 小字"已完成 23/64 · 失误 2 次"，底部一长串规则说明 | 关键信息（目标数字）不够主角；规则常驻是新手负担，老手噪声 |
| 动效语言单一 | 只有 `scale` 与 `shake` | 缺少"演奏"的反馈语汇，趣味无处附着 |
| 层级偏重 | 多层彩色阴影 | 纸感风格应该靠**描边 + 极浅投影**，而不是重阴影 |

**结论**：现有三张卡片造型（方形 / 圆盘 / 图案 Voronoi）是全项目最有价值的差异化资产，**必须保留并强化**；要改的是它周围的配色、HUD 与动效。

### 1.2 模块

- 首页只有「开始挑战」，`findCurrentLevel` 直接决定唯一入口 → 玩家每天看到的是同一屏。
- 排行榜 `pages/rank` 是占位页，但入口存在 → **空壳比没有更伤体验**，v2 先撤掉入口。
- 星星只增不减，`MAX_STARS = 144` 打满后没有任何出口 → 长期玩家失去目标。
- 结算页是"死胡同"：重来 / 下一关 / 返回，没有奖励、没有分享、没有"下一件想做的事"。
- 没有新手引导：首次进入直接进对局，靠底部长文案解释规则。

### 1.3 声音

- 4 个音效由 `scripts/gen-sounds.js` 合成，`click` 是两个高频正弦叠加的"叮"——**是提示音，不是音乐**。
- `InnerAudioContext` 每次播放要 `stop()` 再 `play()`，重复播放同一音高没有"连奏"感。
- 没有音高概念，所以"点对"和"旋律"之间没有关系，浪费了舒尔特方格天然的**序列性**（1→N² 本身就是一条时间轴，天然适合承载旋律）。

## 2. 视觉设计方案

### 2.1 设计方向：**乐谱纸 · 墨水与暖光**

一句话：**一张米白的乐谱纸，数字是墨写的，演奏时纸面上泛起暖光。**

- **底**是纸：`#FBF6EE`，极轻的噪点纹理（CSS `radial-gradient` 模拟，不用图片）。
- **字**是墨：`#1A1815`，数字用等宽数字特性，字重 600。
- **光**是橙：`#E85D2A`，只在三个地方出现——主按钮、点对瞬间的光晕、进度。
- **金**是奖励：`#DFA22E`，只给星星与金唱片。
- **砖红**是唯一负面色：`#BE4438`，只用于点错。

三个约束（写成规范，防止后续走形）：

1. 一屏内**只允许一个强调色**出现，且面积 < 8%。
2. **禁止渐变装饰**（按钮一处渐变除外），纸感靠描边和留白。
3. 任何装饰元素不得落在数字格内部 —— 格子只有数字和纸。

### 2.2 Design Tokens

**色板**

| Token | Hex | 用途 |
| --- | --- | --- |
| `paper-0` | `#FBF6EE` | 页面底色 |
| `paper-1` | `#FFFDF8` | 卡片 / 格子面 |
| `paper-2` | `#F3EADC` | 凹槽、进度底、未点亮槽位 |
| `line` | `#E7DBC8` | 描边、分隔线 |
| `ink-900` | `#1A1815` | 数字、标题 |
| `ink-600` | `#55504A` | 正文 |
| `ink-400` | `#8C8478` | 辅助信息 |
| `ink-200` | `#C6BDAE` | 禁用、锁定 |
| `sunset` | `#E85D2A` | 主按钮、点对光晕、当前进度 |
| `sunset-deep` | `#C4461B` | 按下态 |
| `sunset-soft` | `#FDEDE5` | 浅底强调 |
| `gold` | `#DFA22E` | 星星、金唱片 |
| `brick` | `#BE4438` | 点错 |
| `indigo` | `#3A6EA5` | 双色交替关的"蓝"位（替代现有天蓝，提高纸面协调度） |

对比度：`ink-900` on `paper-1` ≈ 15.8:1，`ink-600` ≈ 8.2:1，`sunset` on `paper-1` ≈ 4.6:1（满足 AA）。所有数字字号 ≥ 22rpx 时对比度达标。

**字阶**（设计稿 750rpx）

| 层级 | 字号 | 字重 | 字体 | 用途 |
| --- | --- | --- | --- | --- |
| Display | 96rpx | 700 | 系统 sans + `tabular-nums` | 对局页「当前目标」 |
| H1 | 56rpx | 700 | **衬线**（Songti SC / Noto Serif SC / serif） | 页面大标题、曲名 |
| H2 | 40rpx | 600 | 衬线 | 卡片标题、唱片名 |
| H3 | 32rpx | 600 | sans | 区块标题 |
| Body | 28rpx | 400 | sans | 正文 |
| Caption | 24rpx | 400 | sans | 辅助、说明 |
| Label | 22rpx | 500 | sans | 角标、标签 |

> 衬线字体只用于"标题与曲名"，是乐谱感的来源；正文一律 sans。小程序不能稳定加载自定义字体（体积 + 首屏），因此走系统字体族 fallback，Android 端退化为 `serif` 也可接受。

**间距**：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64（rpx），页面左右安全边距 32rpx。
**圆角**：格子 12rpx（3×3 时 16rpx）、小卡 16rpx、大卡 24rpx、按钮 999rpx。
**阴影**：只保留两级 —— `0 1rpx 0 rgba(26,24,21,0.05)`（纸面）、`0 8rpx 24rpx rgba(26,24,21,0.06)`（浮层）。**取消所有彩色阴影。**

**动效曲线**

| 名称 | 时长 | 曲线 | 用途 |
| --- | --- | --- | --- |
| press | 120ms | `ease-out` | 按下缩放至 0.96 |
| ripple | 240ms | `cubic-bezier(0.22, 1, 0.36, 1)` | 点对涟漪、音符上浮 |
| enter | 320ms | `cubic-bezier(0.22, 1, 0.36, 1)` | 卡片入场（96% → 100%） |
| celebrate | 480ms | `ease-out` | 结算唱片入场 |
| breathe | 2000ms | `ease-in-out` 循环 | 目标数字呼吸 |

铁律：**任何动画不得超过 600ms**，且不得阻塞下一局的开始（结算页动画不阻塞"再来一局"点击）。

### 2.3 格子状态语言（核心简化）

| 状态 | 底色 | 数字 | 附加 | 说明 |
| --- | --- | --- | --- | --- |
| idle | `paper-1` | `ink-900` | 2rpx `line` 描边 | 唯一常态，全部格子一致 |
| tap（瞬时，<300ms） | `paper-1` | `ink-900` | 内圈涟漪 + 一个 ♪ 上浮消失 | **不改变底色**，保持纸面稳定 |
| error（瞬时，300ms） | `sunset-soft` 微染 | `brick` | 3rpx `brick` 描边闪 2 次 + 横向抖动 5rpx | 不只靠颜色：同时有抖动 + 描边，色盲可辨 |
| done（可选标记） | `paper-1` | `ink-900` @ 38% | 数字下方 2rpx 短线 | **默认关闭**，见下方取舍 |
| 双色关 | 奇数格 `sunset` 系 / 偶数格 `indigo` 系 | 同色系深色 | — | 双色是玩法，不是装饰，保留 |

**关于"是否标记已完成格子"的取舍**

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| A. 完全不变（现状） | 训练纯度最高，历史成绩可比 | 64 格时容易"点重复"，体验略钝 |
| B. 默认标记（数字变淡） | 体验更顺，像真的在"划掉" | 降低搜索难度，**成绩会整体变快，历史最佳失真** |
| **C. 默认关闭 + 设置项（推荐）** | 兼顾；默认不破坏可比性 | 需要多一个开关 |

推荐 C：设置里加「已完成标记」开关，默认关。开启时在结算页标注"标记模式"，成绩单独存一列，避免污染排行。

### 2.4 对局页重构

**现状**

```
┌──────────────────────────────┐
│ 当前目标        剩余时间 00:32 │  ← 目标是小字，时间条是线性
│    12          ▓▓▓▓▓▓░░░░░░   │
│ 已完成 23 / 64 · 失误 2 次  [暂停] │
├──────────────────────────────┤
│                              │
│      5×5 方格（6 色）         │
│                              │
├──────────────────────────────┤
│ 初级·第3关·正序·限时40s·罚时0.15s │  ← 长文案常驻
└──────────────────────────────┘
```

**v2**

```
┌──────────────────────────────┐
│ 星屑 · 初级 3/12        ♪  ◫ │  ← 曲名 + 关卡 + 音乐开关
│                              │
│           ╭──────╮           │
│           │  12  │  ← 96rpx  │  ← 目标数字是绝对主角
│           ╰──────╯           │     外圈 = 环形剩余时间
│         剩余 32″  ✕2         │  ← 失误收进小徽章
│                              │
│  ●─●─●─○─○─○─○─○            │  ← 小节进度（把 N² 拆成 8 小节）
│                              │
│   ┌──┬──┬──┬──┬──┐           │
│   │ 1│ 7│12│23│31│           │
│   ├──┼──┼──┼──┼──┤           │     单色纸面格子
│   │ 5│19│ 4│ 8│17│           │
│   └──┴──┴──┴──┴──┘           │
└──────────────────────────────┘
```

改动点：

1. **目标数字升为 Display 级**，加环形计时包住它 —— 环形是"节拍器"的形状语言，也省下一整行高度。
2. **"已完成 x / N"改为小节进度条**：把 N² 按乐句切成 8 段，点亮即"弹过这一小节"。比数字更符合音乐叙事，也更好扫读。
3. **失误数收成右上角 `✕2` 徽章**，超时前 15% 时徽章变 `brick` 色。
4. **底部长文案只在第 1 关出现一次**（气泡，5 秒后淡出），之后不再常驻。
5. 暂停按钮改为顶部图标，暂停遮罩改为"唱片停转"的视觉（一张静止的唱片 + 继续）。

### 2.5 趣味元素（低成本、高感知）

按"实现成本 / 感知强度"排序，全部不依赖美术资源：

| # | 元素 | 实现 | 成本 | 感知 |
| --- | --- | --- | --- | --- |
| 1 | **音符轨迹** | 点对的格子中心浮起一个 `♪`（文字字符），淡出后留下一个 4rpx 的半透明墨点；8×8 打完全卡，纸面像一页被标记过的乐谱 | 极低（纯 CSS + 文字） | ★★★★★ |
| 2 | **目标呼吸** | 目标数字 2s 周期 1.0 → 1.02 缩放，透明度 92% → 100% | 极低 | ★★★☆ |
| 3 | **连击光环** | 连击 5 / 10 / 20 时目标数字外环亮一圈橙光 0.4s，同时**音色升一个八度**（音乐反馈） | 低 | ★★★★ |
| 4 | **结算唱片** | 星级环绕一张旋转的唱片，唱片标签是曲名 + 评级；金唱片时唱片变金色并有细密纹理 | 中（CSS + 旋转） | ★★★★★ |
| 5 | **关卡唱片角标** | 关卡卡片右上角一枚小唱片图标，已收集点亮，未收集是线框 | 低 | ★★★ |
| 6 | 吉祥物（八分音符小精灵） | 纯几何：两个圆做眼睛 + 一条弧线做嘴，三个表情（专注 / 惊讶 / 欢呼），只出现在结算与暂停 | 中 | ★★★ |

> 建议 v2 先做 1–5，吉祥物放 P2。吉祥物一旦做了就要持续出现，否则会成为"一次性装饰"。

### 2.6 各页面改造清单

| 页面 | 改动 | 优先级 |
| --- | --- | --- |
| 首页（演奏） | 重排为「今日一曲 → 继续闯关 → 曲集进度 → 连续天数」四段式；装饰 9 宫格换成"当前曲目的唱片 + 波形" | P0 |
| 关卡页 | 章节 Tab 保留；关卡卡片增加"曲名段 + 唱片角标"；锁定态文案统一 | P0 |
| 对局页 | 按 2.4 重构 HUD；格子单色化；卡片造型保留（纸 / 瓷 / 墨三种材质微调） | P0 |
| 结算页 | 加"唱片 + 演奏评级 + 旋律回放条 + 收集进度"；按钮顺序保持「再来一局（主）→ 下一关 → 返回」 | P0 |
| 曲集页（新） | 唱片墙：6 张唱片 × 6 段进度；点击播放完整曲；金唱片 / 隐藏曲 | P1 |
| 我的 | 加成就徽章墙、曲集入口；设置项：音效 / 音乐 / 震动 / 已完成标记 / 音色 | P1 |
| 排行榜 | **暂时下掉入口**（空壳页伤体验），等云端方案 | P0（下掉） |

### 2.7 不做清单（防止过度设计）

- ❌ 粒子系统 / canvas 特效：小程序低端机掉帧，收益低于成本。
- ❌ 全屏闪白、全屏抖动：对"专注训练"是负体验。
- ❌ 背景插画、渐变大面积铺底：违背"简洁"。
- ❌ 超过两种字体族。
- ❌ 装饰性 emoji（⭐🔥 等）出现在核心数值旁：换成 CSS 绘制的形状或图标，观感更高级。

## 3. 模块整理

### 3.1 目标信息架构（4 Tab）

```
Tab1 演奏（首页）
 ├─ 今日一曲（每日挑战）      ← 每日回访钩子
 ├─ 继续闯关（主按钮）        ← 主路径
 ├─ 当前唱片进度              ← 收集钩子
 └─ 连续演奏天数              ← 损失厌恶

Tab2 关卡
 ├─ 三档切换（初级/高级/困难）
 └─ 12 关卡卡片（星星 + 曲名段 + 唱片角标）

Tab3 曲集（新）
 ├─ 唱片墙（6 张 + 1 隐藏）
 ├─ 唱片详情：6 段进度 / 完整回放 / 金唱片条件
 └─ 音色选择（星星兑换）

Tab4 我的
 ├─ 统计（星星/通关/场次/连续）
 ├─ 成就徽章墙
 ├─ 最近成绩
 └─ 设置 / 清空 / 关于
```

4 个 Tab 在小程序上限（5）之内。代价：需要新增 2 组 tabBar 图标（8 个 PNG，微信只支持 PNG/JPG）。

> 若不想加 Tab：曲集可并入「我的」，但**收集系统的可见性会大幅下降**，不建议。收集是 v2 的留存核心，值得一个独立入口。

### 3.2 模块调整表

| 模块 | 处理 | 理由 | 留存作用 |
| --- | --- | --- | --- |
| 对局核心 | **保留**（玩法不动） | 引擎已解耦、纯函数、可测 | 基本盘 |

### 3.3 新增模块规格

**① 每日一曲（P0）**

- 每天 00:00 换一首固定曲目（`hash(date) % 曲库`），全服同一首、同一数字布局（种子 = 日期）。
- 每天 1 次"计入成绩"的机会；重玩不计成绩但可继续听（不惩罚）。
- 完成奖励：**音符碎片 ×1**（10 个换一首隐藏曲）。
- 首页入口带倒计时"距离下一首 08:24:11"。
- 与主关卡的关系：独立进度，不消耗星星，不影响主线解锁。

**② 曲集 / 音乐厅（P0，v2 核心）**

- 唱片墙：每档 2 张唱片（共 6 张）+ 1 张隐藏"安可"。
- 每张唱片 6 段进度（对应 6 个关卡），全部点亮 = 唱片变金。
- 点击唱片 → 播放该曲完整演奏（系统按标准 BPM 自动弹，带波形可视化）。
- 未收集的段落显示为"未刻录"，但**可试听前 4 个音**（试听即钩子）。
- 金唱片条件：该曲 6 段全部满星（满星 = 零失误 + 达标，与现规则一致）。

**③ 成就徽章（P1）**

| 徽章 | 条件 | 绑定 |
| --- | --- | --- |
| 初次登台 | 完成首局 | 引导 |
| 完整演奏 | 首次收集一张完整唱片 | 曲集 |
| 金唱片 | 首张金唱片 | 曲集 |
| 零失误 | 8×8 零失误通关 | 玩法 |
| 闪电手 | 5×5 用时 < 20s | 玩法 |
| 七日连奏 | 连续 7 天有对局 | 留存 |
| 安可 | 解锁隐藏曲 | 收集 |
| 满堂彩 | 144 星全满 | 完美主义 |

**④ 新手引导（P0）**

3 屏、共 10 秒、可跳过：① 数字按顺序点 ② 点对会响一个音，全对就是一首曲子 ③ 点错罚时 0.15s。首关固定 3×3，限时放宽到 20s，确保首局 3 星。

**⑤ 分享卡片（P1）**

结算页"分享"生成一张竖版图：唱片 + 曲名 + 评级 + 波形 + 一句"我用了 23.4 秒弹完《星屑》"。小程序用 `canvas` 绘制后 `saveImageToPhotosAlbum`。

### 3.4 留存循环

| 周期 | 循环 | 关键设计 |
| --- | --- | --- |
| **30 秒（单局）** | 听旋律 → 拿星 → 看到下一段 | 每次点击都有音高，即时反馈 |
| **5 分钟（会话）** | 6 关 = 一首完整曲子 | "再打一关就能听完整首"是最强的连续动机 |
| **1 天** | 每日一曲 + 连续天数 | 稀缺性 + 损失厌恶 |
| **7 天** | 一张唱片变金 + 成就 | 中期目标 |
| **30 天** | 全部金唱片 + 隐藏曲 + 音色收集 | 长期身份认同 |

**目标指标**（上线后按此验收）：首关完成率 ≥ 85%，D1 ≥ 35%，D7 ≥ 12%，局均 ≥ 4 局，单次会话 ≥ 6 分钟，曲集完成率（7 日）≥ 25%。

### 3.5 经济系统（补上闭环）

现状：星星只增不减，`MAX_STARS=144` 之后无出口。

```
收入：星星（关卡首通/满星）｜ 音符碎片（每日一曲）｜ 金唱片（成就性，不参与消费）
支出：音色（八音盒 0 / 三角钢琴 30★ / 电钢 60★ / 古筝 100★）
      卡片材质皮肤（纸/瓷/墨 之外的主题，80★）
```

设计原则：**音色只改音色，不改玩法、不影响成绩**。避免"付费变强"式的平衡破坏（虽然这里没有付费，但同理）。

## 4. 音乐系统（核心）

### 4.1 一句话机制

> **每个格子是一个琴键，按 1 → N² 点击，就是把这首曲子从头弹到尾。**

- 关卡不再只是"64 个数字"，而是"**一首曲子的 64 个音符**"。
- 数字 `k` 对应乐谱第 `k` 个音（音高、时值、力度都由曲子决定，不是随机音）。
- 玩家点击速度自由，音乐自然连贯；点错不出音（或出"哑音"），罚时照旧。

### 4.2 音符映射规则（关键设计）

| 玩法 | 映射 | 听感 |
| --- | --- | --- |
| `forward` 正序 | `step = value` | 正常演奏 |
| `reverse` 倒序 | `step = total - value + 1` | **仍然是正着走的旋律** |
| `alternate` 双色 | `step = value`；奇数格取旋律轨、偶数格取低音轨 | 双手交替的二声部 |

> **这是整个系统能成立的前提**：如果倒序关真的"倒放音乐"，玩家会听到一串无意义的音符。用「数字 ↔ 乐谱位置」的反向映射，玩法变体与音乐顺序解耦——**乐谱永远是正序，只有数字的排列在变**。

双色关更妙：奇偶分色天然对应"右手旋律 / 左手低音"，红色是旋律、蓝色是伴奏，交替点击就是双手交替。**玩法与音乐在这里是同一个东西。**

### 4.3 曲库结构：方案对比

| 方案 | 结构 | 内容量 | 收集叙事 | 评价 |
| --- | --- | --- | --- | --- |
| A. 每关独立曲 | 36 关 = 36 首短曲，长度 = N² | 36 段（约 1100 音） | 弱（每关一首，听完就完） | 内容量大，收集感碎片化 |
| **B. 组曲渐进（推荐）** | 每档 12 关 = 2 首完整曲；前 6 关逐段展开曲 A，后 6 关是曲 B 的变奏 | 6 首完整曲 + 6 段变奏（约 800 音） | **强**：打完 8×8 才听到整首 | 内容量可控，天然形成"拼图" |

**推荐 B**，因为它精确回答了用户想要的"不同个数的关卡对应不同的曲子"：**数字越多的关卡，曲子越完整。**

| 关内序号 | 尺寸 | 音符数 | 曲目 | 段落 |
| --- | --- | --- | --- | --- |
| 1 | 3×3 | 9 | 曲 A | 主题动机（必须是可辨识的前 9 音） |
| 2 | 4×4 | 16 | 曲 A | 主题 + 应答 |
| 3 | 5×5 | 25 | 曲 A | 呈示部 |
| 4 | 6×6 | 36 | 曲 A | 发展部 |
| 5 | 7×7 | 49 | 曲 A | 再现部 |
| 6 | 8×8 | 64 | 曲 A | 全曲（含尾奏） |
| 7~12 | 3×3→8×8 | 9~64 | 曲 B | 变奏（倒序=逆行变奏 / 双色=二声部） |

内容设计铁律：**每首曲子的前 9 个音必须是可辨识的主题句**（如《小星星》的 `1 1 5 5 6 6 5`）。3×3 首关就要让人"咦，这是那首曲子"，惊喜感全部集中在开局 15 秒。

曲库规模：3 档 × 2 首 = 6 首完整曲（每首 64 音）+ 6 段变奏。收藏页 6 张唱片，每张 6 段。

### 4.5 音频引擎

**平台能力矩阵**

| 平台 | 方案 | 延迟 | 包体增量 |
| --- | --- | --- | --- |
| H5 | WebAudio `OscillatorNode` 实时合成 | < 10ms | 0 |
| 微信（基础库 ≥ 2.19） | `wx.createWebAudioContext()` 实时合成 | 10~30ms | 0 |
| 微信（低版本）/ 抖音 / 支付宝 | `InnerAudioContext` + 预生成音符 WAV（按曲目用到的音高集合，约 24 音/档） | 50~150ms | ~400KB（放分包） |
| 全部失败 | 退化为现有 `click` 音效 | — | 0 |

**音色合成参数（钢琴近似）**

```
振荡器：triangle（基频）+ sine（2×、3×、4× 谐波，幅度 0.38 / 0.16 / 0.06）
包络 ADSR：attack 6ms / decay 220ms / sustain 0.28 / release 320ms（低音 ×1.4）
滤波：lowpass 4kHz, Q 0.7
击弦噪声：10ms 白噪 + highpass 1.8kHz，增益 0.04
混响：feedback delay 90ms, feedback 0.2, wet 0.12
总线：DynamicsCompressor（threshold -18dB, ratio 3）
单音峰值：-14dBFS
```

四种音色只改三件事：波形组合、包络、混响湿度。

| 音色 | 波形 | 特征 |
| --- | --- | --- |
| 八音盒 | sine + 3×(0.25) | 短促、清脆，release 180ms |
| 三角钢琴 | triangle + 谐波 | 默认，有击弦噪声 |
| 电钢 | sine + 2×(0.5) + 轻微颤音 | 圆润，sustain 高 |
| 古筝 | Karplus-Strong 拨弦 + 快速衰减 | 明亮、带"扫弦"感 |

**性能与稳定性**

- 单例 `AudioContext`，页面 `onHide` → `suspend()`，`onShow` → `resume()`。
- 声部池 8 个，超出时抢占最旧的（8×8 极限手速约 2~3 音/秒，池足够）。
- 连击密集时总线自动 -3dB，防止削波。
- 首帧不预加载任何音频（合成方案零加载）；切到采样降级时才按档预载。
- 小程序静音键：调用 `wx.setInnerAudioOption({ obeyMuteSwitch: false })`，让游戏音在静音键下仍可发声（游戏类常规做法），并在设置里给"静音"开关兜底。

### 4.6 节奏与演奏评级

**问题**：如果完全自由节奏，玩家点得快时音乐就变成"快进"，一首曲子会被弹成 15 秒的杂音。

**解法（不惩罚，只加分）**：

- 每关有一个"参考 BPM"（来自曲子），目标音符间隔 = `60 / bpm × beats`。
- 每次正确点击记录 `delta = 实际间隔 - 目标间隔`。
- 判定：`|delta| ≤ 80ms` → **Perfect**；`≤ 160ms` → Good；否则 Free（不扣分）。
- 结算给"演奏评级"：Perfect 占比 ≥ 70% → **S**；≥ 45% → **A**；≥ 25% → **B**；否则 C。
- 评级**不影响星级**，只影响：① 结算页的唱片光效（S 有金色音符粒子）② 金唱片的"金"色深浅 ③ 成就。

**为什么不做强制节拍**：舒尔特的核心是"用最短时间"，强制节拍会与"比谁快"直接冲突。**让音乐跟着玩家的手走，评级只是给"弹得好听"的人一条额外的荣誉线。**

**可选增强（P2）**：底部极细的节拍指示条（不是必须踩点，只是视觉提示），设置里可关。

- 体验：首关 3 星率 ≥ 70%；第 6 关（听完第一首完整曲）到达率 ≥ 45%。
- 数据：D1 ≥ 35%，D7 ≥ 12%，局均 ≥ 4。

## 6. 风险与待确认

### 6.1 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 小程序 WebAudio 兼容性 | iOS 静音键下无声、部分机型不出声 | 双通道（WebAudio + 采样降级）+ 真机矩阵验证（iOS 15/16/17、Android 低端机） |
| 音乐干扰"专注训练"定位 | 老用户觉得吵 | **不播 BGM**；音乐可单独关闭（与音效开关分离）；默认音量 -6dB |
| 视觉简化导致成绩变快 | 历史最佳失真 | 默认不做已完成标记；存档加版本号，v2 首次进入提示"视觉升级，历史成绩保留" |
| 曲库版权 | 审核/下架风险 | 一半以上原创生成；公版曲目标注来源 |
| 曲库内容工作量 | 6 首 64 音曲子手写成本高 | 写 `gen-songs.js` 用和弦进行生成，人工只做"主题句 9 音"的挑选与打磨 |
| 64 音连点的音频并发 | 低端机爆音/掉帧 | 声部池 8 + 总线压缩 + 密集时自动降混响 |

### 6.2 待你确认的 4 个决策

1. **格子是否彻底单色化？** 现有 6 色循环是"儿童感"来源，去掉后更高级但更"冷"。备选：单色为默认，设置里保留"彩色数字"开关给亲子模式。
2. **曲库版权路线**：全部原创生成（零风险、零成本，但缺少"一听就认出来"的名曲），还是 3 首公版名曲 + 3 首原创（记忆点强，但需确认改编合规）？
3. **是否加第 4 个 Tab（曲集）**？加则收集系统可见性最高，但要新增 8 个 tabBar 图标资源。
4. **音乐是否参与评价**？本方案建议"只影响演奏评级，不影响星级"。若你希望音乐成为核心评价维度，需要重新设计星级公式（会影响现有 144 星体系）。
