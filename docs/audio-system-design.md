## 1 现状体检

### 1.1 现有音频链路

```
点击格子 ──► useGameEngine.tap()
              └─► getNoteForValue(song, level, value)   ← 数字 → 音高（utils/music.ts）
                    └─► playNote(midi, velocity)         ← WebAudio 实时合成（services/audio.ts）
                          └─► melodyBus → limiter → 扬声器
                                   ↑
                              delay(0.09s) 反馈混响（wet 0.14）

曲集回放 ──► playSong(song, {beats})                ← 64 个 setTimeout 逐个触发
              ├─ 每音 playNote(0.62)
              └─ 每 4 音 playChord(0.16)  ← 这就是"伴奏"的全部

提示音 ──► playSound(tick/click/error/success)      ← base64 WAV + InnerAudioContext
```

### 1.2 六首曲子的体检数据

用 `melody` 对 `chords` 逐音核对（强拍非和弦音 = 每小节第 1 拍不在和弦上；半音摩擦 = 与和弦根音构成 1/11 半音的非和弦音）：

| 曲目 | 调性标注 | 实际 | 强拍非和弦音 | 半音摩擦 | 问题定位 |
| --- | --- | --- | --- | --- | --- |
| s1a 纸飞机 | C 大调 | C 大调 ✅ | 4 | 1 | 全在 bar 8–11 |
| s1b 雨后 | D 大调 | D 大调 ✅ | 1 | 5 | bar 9 / bar 2,6,14 |
| s2a 旋转木马 | F 大调 | F 大调 ✅ | 5 | 6 | bar 1,5,9,10,13 |
| s2b 旧唱片 | a 小调 | a 小调 ✅ | 1 | 1 | bar 9 / bar 11 |
| s3a 齿轮 | **D 大调 ❌** | **d 小调** | 5 | 6 | 调性标错 + bar 1,5,9,10,13 |
| s3b 夜航 | **E 大调 ❌** | **e 小调** | 5 | 0 | 调性标错 + bar 1,5,9,10,13 |

规律非常整齐：**问题集中在 bar 1 / bar 8–11**，正好对应生成器的两个"手工覆盖"动作（见 §2）。

## 2 问题一：音符是否正确

### 2.1 错误 A — 调性标注错（2 首）

`scripts/gen-songs.js` 的调性表只按**主音**查，不看大小调：

```js
const KEY_NAMES = { 60:'C 大调', 62:'D 大调', 65:'F 大调', 64:'E 大调', 57:'a 小调' };
```

`SPECS` 里 s3a 是 `root:62, mode:'minor'`（D 小调）、s3b 是 `root:64, mode:'minor'`（E 小调），但 `KEY_NAMES[62]` / `KEY_NAMES[64]` 只会返回大调名。曲集和对局页都在显示这个错误标签。

**修法**：表改成 `(root, mode)` 双键，小调按惯例写小写（`d 小调`、`e 小调`）。零风险。

### 2.2 错误 B — B 段和声错位（6 首全中，最严重）

生成器里 B 句用的是**反转进行**：

```js
const phraseB = buildPhrase(rng, spec.prog.slice().reverse(), 4).notes;
```

但和弦轨一直用**正序进行**：

```js
const chordDeg = spec.prog[bar % spec.prog.length];   // bar 8–11 仍是 prog[0..3]
```

于是 B 段的旋律按 `prog.reverse()` 的和弦写，伴奏却按 `prog` 弹。s1a 的 bar 8 是"旋律落在 F 和弦、伴奏弹 C 和弦"，F 对 C 是 11 度 + 与 B 音半音相撞——**这就是听起来"有个音不对"的根源**，不是错觉。

**修法**（两种，建议 B2）：

- B1：B 句改用正序进行 —— 改动最小，但 A/B 两段和声完全一样，对比只剩音区。
- **B2（推荐）**：`chords` 生成时按段落取进行 —— bar 0–7、12–15 用 `prog`，bar 8–11 用 `prog.reverse()`。旋律一个音都不改，只让伴奏跟上旋律，还白得一段和声对比。

### 2.3 错误 C — hook 覆盖破坏了强拍和声锚点（bar 1）

`buildPhrase` 里每小节首拍本来会吸附到"离上一个音最近的和弦音"，但 A 句前 8 个音随后被 hook 硬覆盖：

```js
for (let i = 0; i < 8; i += 1) phraseA[i] = clampDeg(hook[i]);
```

hook 是相对**主音**的音级，不看 bar 1 的和弦。s2a 的 bar 1 和弦是 B♭，hook 给出 C，C 对 B♭ 是大七度（半音相撞）；s3a 同型，bar 2/6 出现 A 对 B♭。

**修法**：hook 写入后跑一遍**摩擦消除**——若某音与该小节根音构成 1/11 半音且不是和弦音，就移到最近的和弦音（优先保持轮廓方向）。hook 的可辨识度保留，摩擦清掉。

### 2.4 错误 D — 双色关把旋律劈成两半

`utils/music.ts` 里两条轨共用同一个下标：

```ts
const index = Math.min(Math.max(step - 1, 0), line.length - 1);
const line = useBass ? song.bass : song.melody;
return line[index] ?? 60;
```

8×8 双色关（长调后 6 关）点 1..64，偶数格取 `bass[step-1]`，于是**旋律的第 2、4、6…个音永远不响**——玩家听到的是一条"隔一个音跳一下"的残旋律。这不是设计意图，是 bug。

**修法**：两条独立指针（纯函数改动，签名不变、玩法不变）：

```ts
// 奇数格 = 旋律第 k 个音，偶数格 = 低音第 k 个音
const isMelody = value % 2 === 1;
const idx = isMelody ? (value - 1) / 2 : value / 2 - 1;
return isMelody ? song.melody[idx] : song.bass[idx];
```

同时把 `bass` 轨从"每小节重复根音 4 次"改成 **根–五–根–三** 的走动低音，双色关才真的像"左手伴奏"。

### 2.5 缺陷 E — 音色标注与实播不符

- 曲集写死 `TIER_LABELS = { 1:'小令 · 八音盒', 2:'中调 · 钢琴', 3:'长调 · 电钢' }`，但 s3a 的 `style` 是 `piano` 不是电钢。
- 更关键：`playSong` 从不切音色，回放用的是「我的 → 音色」里的用户设置。所以标着"八音盒"的曲子可能用钢琴在响。

**修法**：曲目卡片文案由 `song.style` 派生；回放前临时 `setTimbre(song.style)`，播完恢复用户设置。

### 2.6 缺陷 F — 伴奏和弦抢旋律声部

`playNote` 的所有发声体共用一个 `voices` 池，上限 `MAX_VOICES = 10`。回放时每 4 个音塞 3 个和弦音进去，密集处会把旋律音挤掉（`voices.shift()?.stop()`）。加了伴奏后这个问题会放大 3 倍。

**修法**：拆 `melodyVoices`（上限 12）/ `compVoices`（上限 16）两个池，各自淘汰，互不抢占。

### 2.7 修复后的验收线

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| 强拍**冲突音**（降九度 / 三全音 / 大七度） | 1–5 处/首 | **0** |
| 半音摩擦（任意拍） | 0–6 处/首 | **0** |
| 色彩音（九度 / 十一度 / 十三度） | — | **保留**（全吸附到三和弦会让旋律变木） |
| 调性标注 | 2 处错 | **0** |
| 双色关旋律连续性 | 隔音跳 | **连续 32 音** |
| 音色标注 | 3 档写死 | **按 song.style 派生** |

> 落地时把判定口径收紧到「强拍冲突」而不是「强拍非和弦音」：九度/十一度/十三度是正常和声色彩，
> 在三和弦上不刺耳；真正听起来像弹错的是 1/6/11 半音这三类。口径写在 `scripts/analyze-songs.js` 头部。

## 3 问题二：曲集加伴奏

### 3.1 为什么现在听起来"没有伴奏"

三个原因叠在一起：

1. **太稀**：16 小节只铺 16 次三和弦，每小节 1 次，中间全是干旋律。
2. **太轻**：`playChord(chord, 0.16)`，而 `playNote` 内部还要再乘 0.34 → 实际峰值约 -32dBFS，比旋律低 20dB 以上，基本听不见。
3. **被抢**：和弦的 3 个音和旋律共用 10 个声部的池子（见 §2.6）。

所以不是"没有"，是"有但等于没有"。

### 3.2 伴奏引擎：4 个声部 + 2 条总线

新建 `src/services/accompaniment.ts`，只做一件事：**给定小节号、和弦、绝对时间，把一个完整小节排进音频图**。

| 声部 | 触发位置 | 音源 | 力度 | 包络 | 备注 |
| --- | --- | --- | --- | --- | --- |
| **Bass 低音** | 每小节第 1 拍 | sine + triangle（根音 −12） | 0.50 | A 8ms / D 350ms / R 500ms | 走 compBus 低通，只留厚度 |
| **Pad 铺底** | 每小节第 1 拍 | 和弦 3 音，triangle 叠加 | 0.13 | A 60ms / 持续到小节末 | 混响送得多，退在后面 |
| **Arp 琶音** | 第 2/3/4 拍 | 和弦音 根–五–三–五 | 0.20 | 短音，跟曲目音色 | 让"空拍"有东西在动 |
| **Perc 轻击** | 第 1/3 拍 | 带通噪声短脉冲 | 0.10 | 12ms | 只在长调卷开，纸面感 |

总线：

```
melodyVoices ─┐
              ├─► melodyBus (0.90) ──────────────┐
compVoices ───┴─► compBus (0.55) ─► lowpass ────┤
                     └─► reverbSend (0.18) ──────┤
                                                  ├─► limiter ─► destination
                                                   （threshold −14 / ratio 4）
```

**分段动态**（16 小节，跟着曲子结构走，不是一直一个样）：

| 小节 | 配器 |
| --- | --- |
| 0–3 | Bass + Pad（进场，别一上来就满） |
| 4–7 | + Arp |
| 8–11（B 段） | + Arp + Perc，Pad 力度 +20%（对比段要抬起来） |
| 12–15 | 全开；最后一小节只留 Pad 收长音 |

### 3.3 调度：从 64 个 setTimeout 改成单一 lookahead

现在的 `playSong` 用 64 个 `setTimeout` 逐个触发，定时器抖动 ±15ms 起，长曲子越到后面越飘；伴奏再用一套定时器就会和旋律错开。

**改造**：

- 一个 25ms 的 lookahead 循环，提前 0.2s 把事件排进音频图；
- 旋律与伴奏**全部**用 `osc.start(when)` 的绝对时间，`when` 来自 `ctx.currentTime + offset`；
- `playNote(midi, velocity, when?)` 加一个可选绝对时间参数（不传 = 现在的行为，对局页零改动）；
- UI 进度条仍用 `setTimeout` 近似回调，误差 ±20ms 对进度条无意义。

### 3.4 与「回放我的演奏」对齐（关键）

曲集回放的核心卖点是"放的是你那一遍"，所以伴奏**不能**按 BPM 硬走，必须跟着玩家的击键时间轴：

```
noteTimes[i]  ← 现有逻辑（前 N 个用 beats，超出部分按 BPM 续）
barTimes[b]   = noteTimes[b * 4]        // 4 音一小节
```

- 玩家第 3 小节卡了 5 秒 → 伴奏也跟着停 5 秒再进第 4 小节，这才叫"我的演奏"。
- **不做量化**（不把节奏吸附到网格）。量化会让"回放"变成"另一个人弹的"。
- 只有一处例外：若某小节时长超过 4 拍 × 2.5 倍，Pad 会在 2.5 倍处补一次弱重击，避免长时间死寂。

### 3.5 开关

- 存档新增 `settings.accompaniment`（默认 `true`），SAVE_VERSION 4 → 5，migrate 兜底。
- 曲集每条唱片播放时，右侧显示「伴奏 开/关」小标签，点一下即时生效（重排下一小节）。
- 「我的 → 声音」加一行开关：「伴奏 · 回放时的低音与和声」。
- **对局页不加伴奏**（见 §7 待确认项）。

## 4 问题三：版权

### 4.1 结论

**当前没有任何侵权风险。** 三类资产逐项判定：

| 资产 | 来源 | 判定 |
| --- | --- | --- |
| 6 首曲子（melody/bass/chords） | `scripts/gen-songs.js` 用 mulberry32 确定性算法生成 | 独立创作，无第三方素材 |
| 4 个音效（tick/click/error/success） | `scripts/gen-sounds.js` 用正弦波 + 包络合成 PCM | 独立创作，无采样 |
| 演奏音色 | `services/audio.ts` 运行时 WebAudio 振荡器合成 | 不涉及任何音色库授权 |

代码里没有一处引用外部音频文件、采样包或乐谱。

### 4.2 但要补三件事

1. **证据链**：新增 `docs/audio-license.md`，记录每首曲子的生成参数（seed / prog / hook / 生成时间 / 脚本版本）。万一被质疑，这份文件就是"独立创作"的时间戳。
2. **相似度自查**：算法生成 ≠ 绝对安全。旋律撞句仍可能被指"实质性相似"。新增 `scripts/audio-similarity.js`：把 64 音转成**音程串**（相邻音的半音差），与一份"高危动机库"（常见流行/影视/游戏主题的音程串）做最长公共子串比对。**连续 ≥ 8 音重合即报警**。每次改 hook 后跑一次。
3. **红线写进规范**：见 4.3。

### 4.3 红线（以后加曲子必须遵守）

- ❌ 流行歌曲、影视配乐、游戏配乐（久石让、周杰伦、各类 OST）——一律不碰，哪怕"只用了 4 小节"。
- ❌ 现成录音、采样包、音色库（哪怕标 CC-BY，署名义务 + 包体膨胀都不划算）。
- ❌ 他人的"民歌改编版"编曲（民歌旋律是公有的，但某个合唱团/歌手的编曲版本受保护）。
- ✅ 公有领域原作旋律 + **我们自己**重新记谱与编配。
- ✅ 算法生成 + 相似度自查通过。

### 4.4 关于名曲的版权边界

以《卡农》为例：

- 帕赫贝尔死于 1706 年，作品早已进入公有领域（中国：作者死后 50 年；欧美：70 年）→ **旋律本身随便用**。
- 但**某个乐团/某张唱片的录音**、**某本乐谱的编配**是新的版权客体 → 不能用。
- 我们的做法：只取旋律骨架，和声进行与配器全部自己写 → 我们对"本项目的编配"享有权利，也不侵犯任何人。

## 5 问题四：新增名曲（战绩解锁）

### 5.1 选曲原则

1. 作者逝世逾 70 年（中国逾 50 年），旋律明确进入公有领域；
2. 单声部旋律能独立成立（舒尔特是"一个数字一个音"，复调作品会散）；
3. 8×8 = 64 音能装下完整主题（16 小节 × 4 音）；
4. 气质跟"古风谱纸"不打架——中西各半。

### 5.2 六首曲目

| # | 曲名 | 原作 | 年份 | 调 / BPM | 编排要点 | 解锁条件 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 欢乐颂 | 贝多芬《第九》第四乐章 | 1824 | C 大调 / 100 | 主题 4 句 AABA；Pad 走 I–IV–V–I | 累计 **24 星** |
| 2 | 小步舞曲 | 佩措尔德（旧署巴赫 BWV Anh.114） | c.1720 | G 大调 / 108 | 三拍子感用 Arp 三连做出 | 累计 **48 星** |
| 3 | 致爱丽丝 | 贝多芬 | 1810 | a 小调 / 76 | 保留半音经过句；Pad 压到最轻 | 累计 **72 星** |
| 4 | 绿袖子 | 英格兰民谣 | 16 世纪 | a 小调 / 88 | 6/8 量化为 4/4，长句为主 | 累计 **96 星** |
| 5 | 卡农 | 帕赫贝尔 | c.1680 | D 大调 / 72 | 固定低音 D–A–Bm–F#m–G–D–G–A（两遍）；Arp 必须开 | **1 张金唱片** |
| 6 | 茉莉花 | 江苏民歌 | 清代 | C 大调 / 84 | 五声音阶；Pad 用挂留音，别加三度 | **8 关 S 评级** |

**门槛可达性校验**（满星总数 144 = 12×3 + 12×4 + 12×5）：

- 24 星 ≈ 小令前 8 关满星；48 星 ≈ 小令满星 + 中调 3 关；72 星 ≈ 小令 + 中调前 9 关；96 星 ≈ 前两卷满星 + 长调 3 关。
- 1 张金唱片 = 一首曲子 6 关全部满星，是"专精"指标。
- 8 关 S 评级是"节奏感"指标，跟星级互补，给不同擅长的玩家各一条路。

### 5.3 数据结构

```ts
// types/game.ts 新增
export type ClassicUnlock =
  | { kind: 'stars'; value: number }
  | { kind: 'gold'; value: number }
  | { kind: 'grade'; grade: 'S'; value: number };

export interface ClassicSong extends SongConfig {
  composer: string;   // 原作署名，如 '贝多芬 · 1824'
  unlock: ClassicUnlock;
}
```

- 新建 `src/data/classics.ts`（手写 64 音，不进 `SONGS` —— `getSongForLevel` 按下标取曲，混进去会错位）。
- 新建 `src/utils/classics.ts`：`getClassicProgress(song, save)` 返回 `{ unlocked, current, target, label }`，**全部由现有存档现算**（`stars` / `grades` / `bestRuns`），存档不新增字段。
- 曲集页在 6 张唱片下方新增「名曲拾遗」区块：未解锁显示条件 + 进度条，解锁后可播（走同一个 `playSong`，带完整伴奏）。

### 5.4 为什么不做成关卡

关卡 = 星级 + 限时 + 解锁链，加进去会打乱 36 关的难度曲线和星星门槛（`starGate` 8/16、`MAX_STARS` 144 都要重算）。名曲定位是**收藏奖励**，只进曲集，不动玩法。
